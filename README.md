# SafeCross AI

تطبيق أندرويد (Kotlin + XML) يستخدم كاميرا الموبايل حتى يكشف المركبات ويحذّر الماشي من السيارات اللي دا تقرب عليه.

> **التطبيق بس يساعدك.** إذا ما طلع تنبيه، هذا ما يعني العبور آمن. باوع بعينك دائماً.

## شلون يشتغل

1. الكاميرا تلقط صورة، ونموذج **EfficientDet-Lite0** (عبر MediaPipe) يكشف السيارات والشاحنات والباصات والدراجات. النموذج موجود في `app/src/main/assets/`.
2. `VehicleTracker` يتابع كل مركبة من صورة لصورة، ويحسب هل هي **واقفة** أو **دا تقرب** أو **دا تبتعد** أو **دا تعبر بالعرض**.
3. `RiskEngine` يقرر مستوى الخطر:
   - **خطر**: مركبة دا تقرب والوقت المتبقي لوصولها 4 ثواني أو أقل.
   - **انتبه**: مركبة دا تقرب ببطء، أو دا تعبر، أو قريبة وحركتها بعد ما معروفة.
   - **بدون تنبيه**: سيارة واقفة أو دا تبتعد. السيارة الواقفة ما تطلّع تنبيه حتى لو كانت كبيرة بالصورة.
4. `PhoneSteadiness` يقرا الجايروسكوب والتسارع. إذا الموبايل دا يتحرك، يمسح التطبيق تاريخ الحركة ويطلب منك تثبّت الموبايل، لأن حركة الموبايل تبين كأنها حركة السيارات.
5. السرعة بالكم/س تنعرض **بس** إذا كانت معايرة الكاميرا صالحة، والقياس نظيف، والموبايل ثابت. بغير هالحالة ما ينعرض أي رقم.

التفاصيل الكاملة والمعادلات موجودة في [docs/RISK_ENGINE.md](docs/RISK_ENGINE.md).

## الخصوصية

- كل المعالجة على الموبايل نفسه، وما يُرفع أي فيديو أو صورة.
- الصلاحيات: الكاميرا بس، ومعها الاهتزاز وهي صلاحية عادية. حساسات الحركة ما تحتاج صلاحية.

## البناء (من الموبايل)

كل `push` يشغّل GitHub Actions (`.github/workflows/build.yml`). هذا الـ workflow:

1. يشغّل اختبارات الوحدة `testDebugUnitTest`.
2. يبني `app-debug.apk`.
3. يرفع الـ APK وتقرير الاختبارات كـ Artifacts.

حتى تنزّل التطبيق: افتح تبويب **Actions**، ثم آخر تشغيل ناجح، ثم **Artifacts**، ثم `app-debug`.

البناء من الحاسوب: `./gradlew testDebugUnitTest assembleDebug`، والناتج يطلع في `app/build/outputs/apk/debug/app-debug.apk`.

## هيكل الكود

| الملف | الشغل |
|---|---|
| `MainActivity.kt` | الكاميرا، والواجهة، والتنبيه بالصوت والاهتزاز |
| `detect/VehicleDetector.kt` | كشف المركبات بـ MediaPipe |
| `camera/FrameConverter.kt` | تحويل الصورة وتدويرها بدون حجز ذاكرة جديدة لكل صورة |
| `risk/VehicleTracker.kt` | متابعة كل مركبة وحساب حركتها |
| `risk/RiskEngine.kt` | قرار الخطر |
| `risk/CameraCalibration.kt` | معايرة الكاميرا (مجال الرؤية) لتقدير المسافة والسرعة |
| `risk/PhoneSteadiness.kt` و `sensor/PhoneMotionMonitor.kt` | معرفة هل الموبايل ثابت |

## النسخ الاحتياطية

قبل كل تعديل كبير تنحفظ نسخة بـ tag. طريقة الرجوع لها مشروحة في [docs/RESTORE.md](docs/RESTORE.md).

## حدود معروفة

- كل العتبات تقريبية، وبعدها ما انعايرت على شارع حقيقي.
- التطبيق يفترض إن الماشي واقف على الرصيف وماسك الموبايل ثابت.
- إذا الموبايل ما بيه جايروسكوب ولا حساس تسارع، ما يكدر التطبيق يميّز حركة الموبايل.
- بالليل، أو بالمطر، أو إذا كانت السيارة مخفية ورا شي، الكشف يضعف.
